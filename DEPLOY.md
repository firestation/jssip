# Установка и развёртывание

От чистого сервера до работающей ссылки `https://ваш-домен/`. Все адреса, логины
и пароли в этом файле — **примеры**; свои значения держите в `.env` и в конфиге
сервера, в репозиторий они не попадают.

**Что здесь есть:** сборка, параметры `.env`, требования к медиа (HTTPS),
TURN/STUN, выкладка статики, обновление.
**Чего здесь нет:** настроек веб-сервера и способов ограничить доступ. Это
инфраструктура конкретной установки, а не свойство приложения — каждый настраивает
её под себя. Приложение отдаётся обычной статикой из `out/`.

## 1. Что нужно

**Рабочая машина (где собираете):**

| Что | Версия | Зачем |
|---|---|---|
| Node.js | 18+ (проверено на 22) | сборка |
| npm | идёт с Node | зависимости |
| rsync, ssh | любые свежие | выкладка на сервер |

**Сервер (где хостится):**

| Что | Версия |
|---|---|
| любой веб-сервер | статика + HTTPS |
| coturn | 4.5+ (или любой TURN/STUN) |
| DNS-запись | домен указывает на IP сервера |
| TLS-сертификат | Let's Encrypt или свой |

Важно: **страница обязательно по HTTPS**. Браузер не отдаёт микрофон и камеру
на `http://` (кроме `localhost`), и звонок не начнётся.

SIP-сервер (АТС) — отдельно, JsSIP подключается к нему через WebSocket (`wss://`).
Нужен рабочий WSS-эндпоинт вида `wss://ваш-sip-сервер/ws`.


## 2. Сборка локально

```bash
git clone git@github.com:ваш-логин/jssip.git
cd jssip
npm install
```

Рекомендуемая версия JsSIP — **3.13.x** (проверено на 3.13.9), в `package.json`
стоит `^3.13.9`: версия не закреплена, `npm install` возьмёт свежую совместимую.
Проверить, что поставилось:

```bash
node -e "console.log(require('jssip/package.json').version)"
```

Создайте `.env` из шаблона и заполните своими значениями:

```bash
cp .env.example .env
chmod 600 .env
```

```ini
# .env — подставляется в index.html при сборке
TURN_URL_UDP=turn:turn.example.com:3478?transport=udp
TURN_URL_TCP=turn:turn.example.com:3478?transport=tcp
TURN_STUN=stun:turn.example.com:3478
TURN_USER=jssip
TURN_PASS=придумайте-пароль

# куда выкладывать (для deploy/deploy.sh)
HOST=app.example.com
KEY=~/.ssh/id_ed25519
APP_DIR=/var/www/jssip
```

`.env` в `.gitignore` — в репозиторий не попадёт. Если TURN пока нет, оставьте
`TURN_*` пустыми: сборка не подставит серверов, приложение возьмёт только
host-кандидатов, а ICE-серверы можно вписать вручную в панели настроек.

Сборка:

```bash
npx gulp prod     # минифицированная версия в out/
npx gulp dev      # версия с sourcemap, для отладки
```

Готовое приложение — всё содержимое `out/`.


## 3. Проверка локально

```bash
npx gulp live
```

Откроется `http://localhost:8080/`. На `localhost` браузер разрешает микрофон
по http, поэтому можно сразу звонить.

Проверка сборки и линтера:

```bash
npx gulp lint     # в исходном upstream 2 замечания — это норма
```

Дальше — открыть страницу в браузере и убедиться, что логин, настройки и звонок
работают. Автоматические проверки интерфейса в репозиторий не входят.


## 4. Выкладка

Приложение целиком статическое: скопируйте содержимое `out/` в каталог на сервере.

```bash
sudo mkdir -p /var/www/jssip
rsync -az --delete ./out/ root@app.example.com:/var/www/jssip/
```

Требования к раздаче — минимальные:

* файлы доступны по HTTP(S) как есть;
* **`index.html` не кэшируется** (`Cache-Control: no-store`), иначе после
  обновления пользователи останутся на старой сборке;
* остальную статику можно кэшировать;
* всё по HTTPS.

Все пути внутри приложения **относительные** (`resources/fonts/...`,
`tryit-jssip.js`), поэтому `out/` работает и в корне домена, и в подкаталоге
(`/jssip/`, `/softphone/`) — подкорректируйте отдачу каталога на своём
веб-сервере под выбранный префикс.

Какой веб-сервер, как закрывать доступ и куда класть файлы — вне этого
репозитория: это настройка вашей инфраструктуры.


## 5. TURN/STUN (coturn)

Без TURN звонок работает, только пока обе стороны в простых сетях. За симметричным
NAT и на мобильном интернете нужен релей.

Установка:

```bash
sudo apt install coturn
sudo systemctl enable --now coturn
```

`/etc/turnserver.conf` — минимум:

```ini
listening-port=3478
# внешний адрес сервера
external-ip=203.0.113.10
# диапазон релея
min-port=49152
max-port=65535
# аутентификация по логину/паролю
lt-cred-mech
realm=app.example.com
# пользователь
user=jssip:придумайте-пароль
# TLS (необязательно, но полезно)
# cert=/etc/letsencrypt/live/app.example.com/fullchain.pem
# pkey=/etc/letsencrypt/live/app.example.com/privkey.pem
```

Файрвол:

```bash
sudo ufw allow 3478/udp
sudo ufw allow 3478/tcp
sudo ufw allow 49152:65535/udp
```

Тот же логин/пароль пропишите в `.env` (`TURN_USER`, `TURN_PASS`) и пересоберите
приложение — значения подставятся в `index.html` при сборке.

Проверить, что релей живой:

```bash
turnutils_uclient -u jssip -w пароль -t -y turn.example.com
```

### Что важно знать про сбор ICE

В настройках приложения есть два параметра:

* **«Завершать сбор ICE по srflx»** — как только получен первый публичный кандидат,
  сбор считается законченным и INVITE уходит, не дожидаясь полного
  `iceGatheringState = complete`. Это критично: с включённым STUN/TURN браузер
  держит `complete` до ~40 секунд, и без этого звонок упирается в таймер B (32 с).
* **«Таймаут сбора ICE, мс»** — страховка: если srflx так и не пришёл, сбор
  всё равно завершается по таймеру, а звонок продолжается (не рвётся).

Оба параметра меняются на лету в панели настроек.


## 6. Автоматический деплой

[`deploy/deploy.sh`](./deploy/deploy.sh) собирает и выкладывает статику одной
командой — без настроек веб-сервера:

```bash
HOST=app.example.com \
KEY=~/.ssh/id_ed25519 \
APP_DIR=/var/www/jssip \
./deploy/deploy.sh
```

Что делает:

1. `npx gulp prod`;
2. `rsync --delete` содержимого `out/` в `APP_DIR` на сервере.

Значения по умолчанию: `KEY=$HOME/.ssh/id_ed25519`, `APP_DIR=/var/www/jssip`.
Хост обязателен, иначе скрипт остановится с подсказкой. Ничего, кроме копирования
файлов, скрипт на сервере не меняет.


## 7. Размещение на сайте

Приложение можно повесить в корень отдельного домена или в подкаталог. В обоих
случаях `out/` копируется как есть — код править не нужно, все пути относительные.

* **корень**: `https://soft.example.com/`
* **подкаталог**: `https://app.example.com/jssip/`

Как именно это настроить (rewrite, `try_files`, алиасы, прокси) зависит от вашего
веб-сервера и в репозитории не фиксируется.


## 8. Обновление и откат

Обновление:

```bash
git pull
npm install
./deploy/deploy.sh
```

Откат: на сервере держите копию предыдущей сборки.

```bash
# перед деплоем
ssh root@app.example.com 'cp -a /var/www/jssip /var/www/jssip.prev'

# если новая версия плохая
ssh root@app.example.com 'rm -rf /var/www/jssip && mv /var/www/jssip.prev /var/www/jssip'
```


## 9. Ожидание STUN ~40 секунд

Однажды настроенный TURN делает сбор ICE заметно дольше: браузер держит
`iceGatheringState = complete` до ~40 секунд. Если не завершить сбор раньше,
звонок не уйдёт (INVITE ждёт SDP) и оборвётся по таймеру B. Поэтому в настройках
включён «Завершать сбор ICE по srflx», а «Таймаут сбора ICE, мс» выставлен около
3000–5000.

Подробный разбор проблем и их решений, накопленный в процессе отладки, —
в [README.md](./README.md), раздел «Журнал проблем».
